# Workflow-builder routing

| User need | This skill does | Boundary or handoff |
|---|---|---|
| New repeatable technical workflow | Onboard and author all six steps | No automatic live execution |
| Improve a workflow | Inspect evidence, revise affected artifacts and checks | Re-review changed code and approvals |
| Resume previous work | Load saved facts and current artifacts | Do not repeat answered questions |
| Package complete outputs | Validate and export a child skill | Installation/publishing remain separate |
| Business qualification or client scoping | Technical requirements contribution | agentic-discovery-skill owns commercial discovery |
| Sequence an engagement across skills | Emit state/artifact handoff | agentic-services-orchestrator-skill owns routing/state |
| Proposal, SOW, or agreement | Provide verified technical contract | Proposal/contract specialists own their documents |
| Kickoff, launch readiness, operational handoff | Provide code, evidence, and limitations | agentic-delivery-skill owns delivery artifacts |
| Sensitive data, credentials, new external tools, production risk | Stop affected external actions; assemble evidence | agentic-security-review-skill, not a universal prerequisite |
| Client billing or token-cost evidence | Provide measured results only | Invoice or ai-usage-ledger-skill |
| Email, envelope, proof, certificates, account management | Provide approved factual handoff only | Relevant specialist; no sends or approvals invented |

Do not replace an already suitable domain skill with a new builder project unless
the user actually requests design or improvement. Use a proposed handoff when a
specialist is not available; do not claim to have invoked it. Creating a new skill
does not register it in the orchestrator or alter any other repository automatically.
